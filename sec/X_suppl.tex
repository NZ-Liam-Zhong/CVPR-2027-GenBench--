\section{Rationale}
\label{sec:rationale}
% 
Having the supplementary compiled together with the main paper means that:
% 
\begin{itemize}
\item The supplementary can back-reference sections of the main paper, for example, we can refer to \cref{sec:intro};
\item The main paper can forward reference sub-sections within the supplementary explicitly (e.g. referring to a particular experiment); 
\item When submitted to arXiv, the supplementary will already included at the end of the paper.
\end{itemize}

\section{Benchmark Manifest and Provenance}
Provide source IDs, scene IDs, task-family labels, task-instance IDs, split assignments, observed/derived flags, source permissions, human timing boundaries, and duplicate groups. Report attempted, rejected, repaired, and released tasks.

\section{Generation and Validation Details}
Provide agent prompts and tool interfaces, search pseudocode, candidate-scoring rules, budgets, physics settings, audit instructions, success-predicate checks, and failed reconstruction examples. Document calibration data separately from validation data.

\section{Policy and Embodiment Configurations}
Provide exact model/API versions, checkpoints, prompts, adaptation declarations, sensors, action interfaces, controllers, robot placement, limits, and compatibility matrices. Include the full evaluation and timeout protocol.

\section{Extended Results and Statistical Procedures}
Provide per-task outcomes, repeated-trial counts, domain and embodiment breakdowns, cluster-bootstrap procedures, sampling-study settings, and paired real-world records. Include unsuccessful cases and exclusions rather than only illustrative successes.

\section{Timing and Cost Accounting}
Provide execution timelines, inference/action overlap, retry and reset accounting, hardware utilization and lifetime assumptions, dated prices, and sensitivity analyses. Separate observed deployment quantities from scenario assumptions.

\section{Reproducibility and Versioned Release}
Provide simulator and dependency versions, immutable manifests, seeds, validator versions, commands, hardware requirements, logs, and known nondeterminism. Keep the submission's benchmark version fixed when the public library expands.
